## 主要解释与质量风险

1. **T2 主要呈现输出格式失败。** Qwen3.5、Qwen3.6、GLM 在三个实验的 T2 无效率均为 100%，所以 0% Pointing Accuracy 目前主要说明答案未形成可解析坐标，不能独立证明它们看不到病灶。InternVL 与 MedGemma 虽有可解析输出，MSD Pointing Accuracy 也仅为 5.0% 与 0.8%。需要原始预测区分提示词不兼容、坐标格式偏差与真实定位失败。
2. **T3 F1 对“全选切片”策略不敏感。** Qwen3.5、Qwen3.6、GLM 在所有分支均有 100% slice recall、恰好 4 层 boundary error；MSD F1 约 61%。对半径 4 的九层窗口，全选 A–I 就会造成这种模式。现有汇总与此一致，但缺原始预测，不能断言每道题都全选。应增加全选基线和选择数量分布，再解释 F1。
3. **T4 的 50% 可能只是位置偏好。** Qwen3.5、Qwen3.6、GLM 在 CARE 两分支各有 80/58 个患者，每个患者的交换配对总是“一题对、一题错”，没有一例两题都对。这个模式与固定回答 A 或 B 相容，不能作为肿瘤/正常壁区分能力。Gemma 两分支分别只有 1.2%、1.7% pairwise accuracy，值得用原始回答检查是否存在系统性解析或图像顺序问题。
4. **T5 的零分与 100% monotonicity 不代表可靠反事实一致性。** 当前 `PipelineVLM.score_choices()` 恒返回 `None`，因此所有模型都走二元决策回退。`eval_t5_groups()` 将缺失/不可解析的 PRESENT 分数也转成 0；原图、病灶抑制、对照抑制都为 0 时，gap=0 且单调性=1 是平凡结果。多数模型的原图 PRESENT 比例为 0。CARE class 2 分支 T5 仅 2 人，任何分数都极不稳定。应报告原图阳性识别率、回退/无效比例和分数模式；在完成适配器级 likelihood 校验前，不把决策回退量表称为连续 Faithfulness Gap。
5. **T1 排序存在已确认的解析错误。** `_labels_from_parsed()` 对非 JSON 答案会从整段原始文本中搜索 A–L 字母，确实把解释文字计为切片标签。现有结果的负例 NONE specificity 除 Gemma 外均为 0。MSD 的 R@3 不宜据此正式排名；后续同步的原始预测审计见下节。
6. **跨次构建复现性存在代码问题。** `build_all_tracks()` 以 Python 内置 `hash()` 派生随机种子；Python 不同进程的哈希随机化可能改变 T1 排列及其他抽样。所有模型在同一已生成 manifest 上比较仍可成立，但跨机器/跨次重建可能不一致。应改为稳定哈希，并保存 manifest 及摘要。
7. **CARE 医学语义仍未确认。** 两分支不能按模型分数高低择优。尤其 T1/T3/T5 的可评价人数差异很大，直接比较两个分支的指标会混入不同样本构成。

## 同步原始预测后的实证审计（2026-09-27）

### 完整性与构建排除

- 三份 manifest 分别有 MSD **2,233**、CARE class 1 **670**、CARE class 2 **441** 个 item；每个模型在每个分支均恰好有对应数量的预测，item ID 无缺失、额外项或重复。
- `benchmark_msd.failures.json` 的 126 条均是 `._colon_*.nii.gz` 元数据文件读取错误；126 个真正的 MSD 患者均进入 manifest。这是数据扫描清理问题。
- CARE test 预期 81 人，但 class 1 manifest 仅 80 人，class 2 仅 58 人。各自 `failures.json` 的 1、23 条均为 `Cannot take a larger sample than population when replace is False`。原因是 T1 构造负例时要求抽取 12 张阴性切片，却未检查阴性池大小；`build_benchmark.py` 按整例捕获异常，因而其他本可构造轨道也一并丢失。这是**构建代码引起的队列排除**，不是数据本身的 81 人队列不完整。

严格重算只采用合法结构化回答，不从解释文字猜答案；无效回答计 0。数字用于诊断，还未替代正式汇总。Qwen 与 GLM 的 T1/T3 原汇总分数是解释文字中的字母被错误拾取后的产物。Qwen 两代原始回答大量从 “The user wants...” 的分析文字开始，GLM 大量从 `<think>` 开始，在 `max_new_tokens=96` 内未给出要求的 JSON。Gemma 的 T2 还有部分坐标 JSON 格式失败。

**T1 指标定义需要更名或更正。** 当前 `recall_at_k()` 实现的是“前 k 个至少命中一个阳性”的二元命中率，而不是 3 个阳性切片的真正召回率。全部 T1 正例题均为 12 张图、3 张阳性；随机排序的命中@3 期望为 `1 - C(9,3)/C(12,3) = 61.8%`。严格评分下 MSD 最好 InternVL 为 64.3%（患者 bootstrap 95% CI 59.0–69.6%），不能据此声称明显超过随机排序。

**T3 简单基线超过所有模型。** 对每道九层题恒选 A–I，在 MSD 的患者平均 F1 为 69.4%。严格评分的最高模型 InternVL 为 66.7%；配对患者差值 −2.75 个百分点（2,000 次 bootstrap 95% CI −4.64 至 −1.09 个百分点）。原 Qwen/GLM 的约 61% F1 由文本字母回退造成，严格评分为 0。

**T4 选择解析也受解释文字和停止标记影响。** Qwen、GLM 在 CARE 配对中每个患者恰好一题正确，原始回答多为未完成的分析文字，解析器从其中的 “A” 得到固定选择。Gemma 的原始输出常为 `B<turn|>`：class 1 的 160 题中至少 154 题、class 2 的 116 题中至少 107 题是这种可直接识别的 `A/B<turn|>` 形式，却大多被记为无效，导致原 1% 左右准确率严重失真。MedGemma 也存在原文明确称 B 更可疑，却因前文出现 A 而解析成 A 的样例。需先修选择解析再报告 T4。

**T5 目前基本不可用于反事实结论。** MSD 原图被解析为 PRESENT 的患者数：Qwen3.5 `0/126`、Qwen3.6 `4/126`、GLM `6/126`、InternVL `0/126`、MedGemma `2/126`、Gemma `0/126`。其中 Gemma 原始 `PRESENT<turn|>` 被解析器漏掉，故其 0 是解析错误的一部分。没有正确识别原图时，病灶抑制后的 0 gap 或 100% 单调性不说明模型关注病灶。当前没有经验证的候选概率评分器，所有 T5 都是决策回退。

## 代码修复与独立重评分（2026-09-27）

- T1 构建现在先检查阳性/阴性池容量；不足 12 张全阴性切片时，只跳过该负例题，不让整例构建失败。该修复需要原始 CARE 数据在计算环境重新构建 manifest 才能验证患者覆盖数。
- 每例随机种子改用 SHA-256 稳定派生；MSD 索引跳过 macOS `._` 元数据文件。
- T1/T3 只接受明确的 JSON 列表或单个 JSON 代码块，不再从解释文字中扫描 A–L。T2 对结构化坐标做数值和范围校验；T4/T5 重新从原文解析明确的单项答案，能识别 `B<turn|>`、`PRESENT<turn|>`，不能确定的回答计为无效。
- T1 的旧 `recall_k` 实为 Hit@k。现在分别报告 `hit_k` 与真正的阳性层面 `recall_k`。T3 增加全选切片基线。T5 无效回答不再被当作 ABSENT；决策式 `decision_gap` 与只有候选似然分数才可计算的连续 `faithfulness_gap` 分开，决策式差值仅在原图被识别为 PRESENT 时计算。
- `python -m pytest -q`：17 passed。用旧 manifest、旧预测独立重评 18 组结果，输出至 `results_strict_20260927/`，原 `results/` 未覆盖；重评使用每项 500 次 bootstrap。新评估仍继承旧 manifest 的 CARE 整例排除，因此不是修复后 CARE 队列的正式新结果。
