# 协议 v2.3 正式实验结果审查（2026-09-28）

## Benchmark 目标是否达到：重新评估

**结论：已达到可复现的 benchmark 原型和失败模式诊断目标，尚未达到完整五轨道正式 benchmark 的发表要求。** 模型低分本身可以是重要发现；阻碍结论成立的是部分任务的参考语义、输出协议、简单基线和预先声明的指标仍不充分。当前结果应作为冻结的 v2.3 基线，不应因分数低而事后改答案或择优选 CARE 标签分支。

| Benchmark 要求 | 当前证据 | 判定 |
| --- | --- | --- |
| 可复现的题目与运行 | 18/18 组完成；21,594 条预测逐题匹配 manifest 指纹；患者层面 bootstrap | 基本达到。结果元数据尚未记录 Git 版本、各模型精确 snapshot revision 和配置哈希。 |
| 可信的参考答案 | MSD 以真实分割掩码构题；CARE 官方数字标签与医学语义尚未对应确认 | MSD 可作核心；CARE 只能保留双分支敏感性分析，不能作为已定语义的主榜。 |
| 任务能检验所宣称能力 | T2 提供点与框的直接空间检验；T1/T3/T4/T5 有明确失败模式 | 部分达到。T1/T3 简单策略很强；T4 位置偏好可获得约 50% 准确率；T5 原图识别覆盖极低。 |
| 所有模型的测量口径可比 | 同一 manifest、贪心生成、严格解析并计入无效率 | 部分达到。Qwen3.5 的 T1–T3 全部无效，MedGemma 的 T4/T5 全部无效；这些轨道的零分主要混合了格式遵从与视觉能力。 |
| 声明的主要指标均可报告 | T1–T3 已有患者层面指标；T4 有准确率；T5 有决策式回退 | 未达到。协议声明的 T4 图片交换一致性尚未写入正式汇总；T5 连续 Faithfulness Gap 因候选似然评分器未验证而不可计算。 |
| 独立开发与最终评价 | `configs/benchmark.yaml` 列出 `dev_msd`/`dev_care`，但构题和运行代码并未使用这两个配置项；预检病例也进入正式评价 | 未达到。后续格式/提示词开发须使用患者隔离的开发集，再冻结协议并在独立患者上评估。 |

MSD 的 T1/T2/T3 可作为下一版 benchmark 的核心，但需要把格式合规率与视觉指标并列报告，并预先固定简单基线。MSD 使用公开的带标注训练集，现有材料不能排除部分模型在预训练阶段接触过相关图像；对外报告须将此列为数据污染风险。T3 的“九层全选”F1 为 69.4%；固定只选中心 E 的 F1 为 35.1%，但因构题窗口始终以边界为中心，其边界误差为 **0 层**。这说明单看 F1 或边界误差都可能奖励不看图的固定策略。T4 必须正式报告交换后是否翻转选择和选边分布；T5 若无法获得可验证的连续分数，应明确降为探索性扰动反应任务，不能以现有决策回退结果宣称视觉忠实性。

满足完整 benchmark 要求的最小下一步是：冻结 v2.3 作审计档案；建立并实际使用患者互斥的开发/正式评估划分；完成 CARE 数值标签核证或保持其探索性地位；加入预先声明的 T1/T2/T3 简单基线及 T4 交换一致性汇总；为所有模型提供事前确定的统一输出协议并同时报告无效率；最后在不接触正式患者结果的条件下运行新版本。模型是否超过基线是研究结果，不是 benchmark 成立的前提。

## 完整性与口径

- Slurm 作业 `156051` 于 2026-09-28 完成；`runs/protocol_v2_3/` 含 6 个模型 × 3 个实验分支，共 18 份评价结果。
- MSD、CARE 标签分支 A、B 的 manifest 分别有 2,233、687、679 题；每个模型在每个分支的预测题数与 manifest 相同，题目 ID 唯一，记录的 manifest 指纹与当前 manifest 一致。合计 21,594 条预测。
- 下表采用 `summary.json` 的患者层面均值。T2 的均匀随机点和中心点基线另从当前 manifest 对应的掩码计算。格式无效的回答按既定协议计入失败，不应被解释成视觉能力为零。

T1 每道正例题有 12 层、3 层阳性；随机排序的 Hit@3 期望为 61.8%。MedGemma 的 65.3% 患者 bootstrap 95% CI 为 60.6%–69.8%，包含这一基线，且其全阴性题 specificity 为 0。其他模型的 Hit@3 也没有明确超过随机基线。Qwen3.5 的 T1、T2、T3 全部格式无效，不能把对应的零分当作视觉性能结论。

T2 掩码平均占全图 0.56%；均匀随机点的预期命中率为 0.56%，中心点命中率为 3.46%。Qwen3.6 的患者平均点命中为 7.4%，相对中心点的配对差为 +3.97 个百分点（5,000 次患者 bootstrap 95% CI +1.06 至 +7.01 个百分点）；这是弱但可检测的定位信号，绝对命中率仍低。GLM 的点命中 5.7%、框 IoU 9.3%；其点命中相对中心点的配对差区间跨零。MedGemma 和 Gemma 的 T2 有大量格式无效回答。

T3 恒选九层的患者平均 F1 为 69.4%，六个模型均未超过。最高的 Qwen3.6 为 67.1%，患者配对差为 −2.34 个百分点（10,000 次 bootstrap 95% CI −4.66 至 −0.25 个百分点）。

T5 在 126 张有标注病灶的原图中，仅 GLM 回答 PRESENT 达到 24 张；Qwen3.5 和 Gemma 各 1 张，Qwen3.6 与 InternVL 为 0 张，MedGemma 原图回答全部格式无效。所有模型只使用决策式回退，没有经验证的候选似然分数，因此连续 `faithfulness_gap` 不可报告。GLM 的 `decision_gap=0.5` 只涉及其识别出的 24 例，其中 12 例为 1、12 例为 0；不代表全部 126 例的反事实效果。

## CARE 敏感性分支

CARE 标签语义仍未由外部标注说明确定；两分支不能按模型分数高低选择“正确”类别。分支 A（标签 1 为肿瘤）有 T1 患者 7、T3 患者 3、T5 患者 28；分支 B（标签 2 为肿瘤）分别为 34、78、3。任务覆盖严重不对称，特别是分支 A 的 T3，不能用于稳健模型比较。

T4 在每个分支都有 81 例 × A/B 交换两题。模型准确率集中在 41%–53%，最高也仅 85/162（52.5%）。Qwen3.5、GLM 和 Gemma 存在明显的 A 或 B 位置偏好：例如 GLM 在分支 A 的 162 题中选 A 148 次，仅 14/81 对在交换图片后改变答案；Gemma 在 75 对两题均有效的样本中 0 对改变答案。MedGemma 两分支的 T4 全部格式无效。约 50% 的准确率主要可由固定选边得到，不能视为识别肿瘤区域。

## 研究结论与下一步

1. 本轮是完整的计算运行，可作为协议 v2.3 的基线与失败模式记录；尚不能支持模型稳定定位结直肠原发肿瘤、CARE 类别语义判断或病灶反事实忠实性结论。
2. 先落实患者互斥的开发/评价划分、参考标签核证及所有轨道的固定基线与预定指标。新协议须在独立患者上冻结后运行。
3. 在开发集上确定统一的结构化输出方案，解决 Qwen3.5 的 T1–T3 和 MedGemma 的 T4/T5 格式问题；正式报告同时展示格式合规率与视觉指标，保留本轮原始预测以供审计。
4. T2 同时报告点命中、框 IoU、无效率和中心点基线；T3 同时报告全选九层及固定中心层基线；T4 正式汇总图片交换一致性与选边分布。T5 将原图识别率作为前置覆盖指标，并在候选似然分数未验证前保持探索性。

数据源：`runs/protocol_v2_3/manifests/`、`predictions/`、`results/` 以及 `slurmlog/156051.out`。CARE 类别语义仍按 `results/all_experiments_summary.json` 标记为未解决。
